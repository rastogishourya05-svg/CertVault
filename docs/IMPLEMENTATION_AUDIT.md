# CertVault implementation audit — 2026-11-15

This is the pre-pipeline audit snapshot. The subsequent disabled-by-default Gmail PDF pipeline is described in [GMAIL_PIPELINE.md](GMAIL_PIPELINE.md) and the latest checkpoint in [IMPLEMENTATION_STATUS.md](IMPLEMENTATION_STATUS.md); live Gmail and positive hosted Storage verification remain outstanding.

**Verdict: a functional local development demonstrator and a limited Supabase account slice, not a production-ready certificate application.** Credentials alone will not complete the missing integrations. No deployment, real mailbox scan, new external Auth account, email, AI call or paid resource was enabled during this audit.

Reviewed all application/API/worker modules, migrations, infrastructure, scripts and tests against PRD.md, ARCHITECTURE.md, SECURITY.md and TEST_PLAN.md. Historical live-account results are explicitly separated from this audit's tests.

## Classification

- **Fully implemented and tested** means the specifically named component works within its stated development scope; it does not certify the complete product for production.
- **Implemented but unverified** means code/schema exists without the required live or release-level evidence.
- **Demo/mock only** means functional synthetic/local behavior, even where it has real persistence and tests.
- **Incomplete** means only part of the requirement is wired end-to-end.
- **Not started** means no usable implementation was found; a schema column alone does not count as a feature.

## Repairs made without credentials

1. Routed local UI searches to the actual API so extracted PDF text and tags are searchable; ignored stale searches and bounded query length. Added API and reload/document-text E2E coverage.
2. Added an owner-scoped favorite-only account endpoint; the UI no longer resubmits stale title/issuer or converts a null issuer to an empty string.
3. Kept data-validation/permission errors distinct from invalid login, and prevented Redis cleanup failures from turning revoked sessions into unhandled server errors. Added focused regressions.
4. Separated account profile loading from certificate searches, prevented stale request results and unsaved preference overwrites, and added an explicit loading state with mocked UI regressions.
5. Isolated the worker smoke queue, forced traces off for credential-bearing live E2E, removed misleading new sample-scan log wording, added the missing icon, shortened the clipped category label and removed production `unsafe-eval` from CSP. Inline-script nonce/hash hardening is still outstanding.

## Prioritized work to reach a functional production application

1. **P0 — unify identity and persistence.** Finish signup/confirmation/recovery; make the actual main vault use authenticated Supabase-backed APIs and private Storage. Implement complete owner-scoped CRUD, pagination, nullable metadata contracts and cloud audit. Do not silently migrate demo files into real accounts.
2. **P0 — secure manual ingestion before mail.** Isolated temporary quarantine, observed/declared/hard bounds, malware scanner, PDF/image sandbox/resource limits, OCR/structured extraction, hash/idempotency, scanned-object storage and authorized download/signing. Verify positive and denied cross-user Storage HTTP paths and cleanup on every failure.
3. **P0 — durable worker pipeline.** Have APIs enqueue jobs; persist transitions/cursors/attempts, cancellation/disconnect semantics, backoff/Retry-After, quotas, notifications outbox and crash/retry/object-store compensation. Test concurrent duplicate processing and restart recovery.
4. **P0 — Gmail, then Microsoft.** Implement consent/scope/range UX, authorization/callback endpoints, encrypted versioned token persistence, refresh/revocation, paging/backfill/incremental jobs and expired-cursor recovery behind disabled-by-default flags. Use mocks until credentials and explicit consented test mailboxes exist; do not enable scans during this audit.
5. **P0 — complete vault/lifecycle UX.** Real document preview, full export, deletion/retention, review/error/expiry notifications/preferences, job progress, loading/error/accessibility journeys and mobile QA across real-account features. Finish links only with a DNS-pinned allowlisted transport; otherwise provide an actionable reference/review fallback.
6. **P1 — verified opt-in features.** Wire hosted profiles/shares/collections/QR and manual social sharing, then consented AI classification/extraction/drafting with validated output, provenance, failure handling and budgets. Never auto-publish.
7. **Release gate — operations/security.** HTTPS/Secure cookies, production origins/CSRF and CSP nonces, managed Redis authentication/TLS and secret rotation, retention/legal/region/license decisions, CI execution, dependency/secret scanning, monitoring/backups/restore drills and provider approval. Resolve/review inherited project advisories without changing unrelated application tables or upgrading plans without consent.
